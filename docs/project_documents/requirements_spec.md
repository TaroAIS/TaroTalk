# 需求规格说明书

## 功能需求
### 前端
- **用户注册与 persona 创建**：用户登录或注册时填写自我描述，前端通过 API 调用生成 persona。
- **通讯录管理**：
  - 自动展示系统生成的 AI 联系人列表。
  - 支持按名称或关键词搜索联系人、按最近互动/在线状态/亲密度排序。
  - 支持分组和标签管理，支持黑名单。
- **聊天功能**：
  - 聊天列表显示最近会话的摘要、未读数和时间戳，可置顶和删除。
  - 聊天界面支持文本、表情、图片、音视频、文件、小程序卡片等消息类型。
  - 支持引用回复、转发、撤回、删除、置顶、批量操作、消息草稿。
  - 支持实时显示输入状态和已读回执，支持单聊和群聊。
- **朋友圈**：
  - 发布图文、视频、链接、定位、话题等动态。
  - 支持点赞、评论、分享、收藏、举报及隐私设置。
  - 实现推荐算法，为用户推荐感兴趣的动态或广告。
- **个人中心**：
  - 显示和编辑头像、昵称、公开标签。
  - 展示 persona 简述和兴趣标签（只读或部分可编辑）。
  - 允许切换通知设置、隐私设置等。
- **AI 代理管理**：
  - 查看各 AI 代理的简介、关系和历史互动。
  - 允许用户屏蔽某些代理或调整接收频率。

### 后端
- **身份认证服务**：提供注册、登录、验证码、OAuth 等接口，基于 JWT 或 OAuth2 进行授权。
- **用户服务**：管理用户基本信息、好友关系、通讯录分组、黑名单。
- **Persona 服务**：生成和存储 persona 文本描述及嵌入向量，提供更新接口。
- **聊天服务**：
  - 会话模型：创建、查询、更新会话（单聊和群聊）；
  - 消息模型：发送、接收、撤回、删除消息；消息状态（已送达、已读）更新；消息历史分页查询；
  - WebSocket 连接管理：与 Presence 服务联合维护在线状态。
- **Feed 服务**：管理动态发布、评论、点赞等，并提供推荐接口。
- **关系服务**：使用图数据库存储关系，提供查询和更新关系权重的接口。
- **通知服务**：向离线用户推送消息，支持 APNs/FCM、短信、邮件。
- **AI 服务接口**：负责整合调用 OpenAI API/其他 LLM，提供生成 persona、生成聊天回复、生成动态内容等接口；管理 Prompt 模板和记忆检索逻辑。
- **Scheduler 服务**：定时任务调度 AI 代理的行为，如自动聊天、动态发布、广告推送。

### Agent
- **数字人格构建**：接收用户描述，通过 Prompt 模板调用 LLM 生成 persona 文本和结构化属性。
- **记忆管理**：当发生事件时，将事件存入记忆池（向量数据库）并标记重要性，定时通过 LLM 进行反思更新。
- **对话生成**：根据 persona、记忆检索结果和当前上下文生成回复；支持多角色参与；需要与聊天服务协同避免重复发送。
- **行为规划**：根据关系网络和计划触发新的对话、群聊或动态；Scheduler 服务定时调用。

## 非功能需求
### 性能
- 支持同时在线10万用户；端到端消息延迟不超过200ms。
- 支持每秒5000条消息写入，保证消息服务的水平扩展。
- Persona 生成和对话生成应在1s内返回初步结果。
- 朋友圈推荐在1s内返回10条动态。

### 安全
- 使用 HTTPS/TLS 加密所有网络传输。
- 用户密码使用盐和哈希加密存储，Token 采用签名验证。
- 对发送内容进行敏感词过滤和图片审核，防止不当内容传播。
- 支持数据加密和脱敏，符合 GDPR/网络安全法等相关法规。

### 可靠性与可扩展性
- 系统可用性≥99.9%，采用主从复制、故障转移、消息重试机制。
- 微服务架构支持水平扩展；无状态服务可自动扩缩容。
- 采用幂等接口设计和事务机制，确保消息不丢失且不重复处理。
- 引入熔断、限流、退避重试等容错机制。

### 可维护性
- 代码遵循分层和领域驱动设计。
- 统一日志格式和集中监控，提供完善的告警。
- 采用配置中心管理配置信息，支持灰度发布和滚动升级。

### 合规性
- 明确标记广告内容，提供用户关闭广告的能力。
- 遵守当地信息安全和个人隐私保护法规，对用户数据提供删除与导出功能。
